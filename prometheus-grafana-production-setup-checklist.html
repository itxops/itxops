Prometheus + Grafana: Production Setup Checklist & Alert Rules

Deploying Prometheus and Grafana takes five minutes; configuring them for real-world production reliability takes thoughtful engineering. Here is our battle-tested setup checklist with Node Exporter hardening and essential Alertmanager rules.

Prometheus has become the uncontested standard for open-source metrics collection in modern cloud architecture. Combined with Grafana for rich dashboard visualization, it delivers granular, second-by-second visibility into your fleet of Linux servers, Docker hosts, and database clusters.

1. Installing & Securing Node Exporter

Node Exporter is the lightweight daemon that runs on each Linux server to expose kernel, disk, memory, and network metrics on port 9100.

bash • install node_exporter 
# 1. Download official release binary
$ wget https://github.com/prometheus/node_exporter/releases/download/v1.8.1/node_exporter-1.8.1.linux-amd64.tar.gz
$ tar xvf node_exporter-1.8.1.linux-amd64.tar.gz
$ sudo mv node_exporter-1.8.1.linux-amd64/node_exporter /usr/local/bin/

# 2. Create unprivileged system user
$ sudo useradd -rs /bin/false node_exporter

# 3. Create systemd service
$ sudo tee /etc/systemd/system/node_exporter.service <
Firewall Protection Required!
Never expose port 9100 to the public internet! It exposes raw host hardware information and active process counts. Allow traffic on port 9100 strictly from your Prometheus server IP: sudo ufw allow from 10.0.0.5 to any port 9100 proto tcp.

2. Production prometheus.yml Configuration

Configure your scrape jobs with consistent evaluation intervals and instance labels:

yaml • /etc/prometheus/prometheus.yml 
global:
  scrape_interval:     15s
  evaluation_interval: 15s

rule_files:
  - "alert_rules.yml"

alerting:
  alertmanagers:
    - static_configs:
        - targets: ['localhost:9093']

scrape_configs:
  - job_name: 'linux-nodes'
    static_configs:
      - targets: ['10.0.0.10:9100', '10.0.0.11:9100']
        labels:
          environment: 'production'

3. Essential Alert Rules Every Server Needs

Add these four golden alert definitions to /etc/prometheus/alert_rules.yml:

yaml • alert_rules.yml 
groups:
- name: host_alerts
  rules:
  # 1. Instance Down (Host Unreachable)
  - alert: InstanceDown
    expr: up == 0
    for: 2m
    labels:
      severity: critical
    annotations:
      summary: "Host {{ $labels.instance }} is unreachable"

  # 2. Disk Running Out of Space (> 85% in 4 hours)
  - alert: DiskFillingUp
    expr: (node_filesystem_free_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100 < 15
    for: 10m
    labels:
      severity: warning
    annotations:
      summary: "Disk space on {{ $labels.instance }} is under 15%"

  # 3. High CPU Load (> 90% for 15 minutes)
  - alert: HostHighCpuLoad
    expr: 100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 90
    for: 15m
    labels:
      severity: warning

  # 4. Out of Memory Danger (< 5% Available)
  - alert: HostOutOfMemory
    expr: node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100 < 5
    for: 3m
    labels:
      severity: critical

4. Top Grafana Dashboard Recommendations

Do not build dashboards from scratch. Import the community benchmark dashboard:

  • Dashboard ID 1860 (Node Exporter Full): The gold standard dashboard featuring CPU usage by core, memory breakdown (buffers/cache/free), disk read/write throughput, and network interface packet drops.
Pro Tip: TSDB Retention Tuning
By default, Prometheus keeps data for 15 days. For production, set --storage.tsdb.retention.time=90d and --storage.tsdb.retention.size=50GB to prevent unexpected disk exhaustion on the monitoring server!
