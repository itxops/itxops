Building a Hardened Self-Hosted Runner on AWS / DigitalOcean for GitHub Actions

GitHub-hosted runners cost $0.008 per minute. For teams running dozens of builds daily, minutes quickly spiral into hundreds of dollars. Here is how to configure a fast, secure, dedicated runner on Ubuntu Linux.

GitHub Actions provides generous free tiers for small projects, but once a development team scales to 5–15 engineers, continuous integration minutes become a significant cost center.

Consider the mathematics: 50,000 CI minutes on standard GitHub Linux runners costs $400/month. A dedicated 4-core, 8GB RAM virtual server on Hetzner or DigitalOcean costs approximately $14–$20/month — delivering unlimited build minutes, local Docker image layer caching, and up to 3x faster build times.

1. The Security Golden Rule for Self-Hosted Runners

CRITICAL SECURITY WARNING
Never use self-hosted runners on public GitHub repositories! Anyone who opens a pull request can run arbitrary malicious shell code with root access on your server. Only deploy self-hosted runners in private repositories or internal organization accounts.

2. Step-by-Step Installation on Ubuntu 24.04 LTS

Always create a dedicated, unprivileged user named actions-runner rather than running the daemon as root:

bash • runner setup 
# 1. Create dedicated user and add to docker group
$ sudo useradd -m -s /bin/bash actions-runner
$ sudo usermod -aG docker actions-runner
$ sudo su - actions-runner

# 2. Download latest actions-runner package
$ mkdir actions-runner && cd actions-runner
$ curl -o actions-runner-linux-x64-2.319.1.tar.gz -L \
    https://github.com/actions/runner/releases/download/v2.319.1/actions-runner-linux-x64-2.319.1.tar.gz
$ tar xzf ./actions-runner-linux-x64-2.319.1.tar.gz

# 3. Configure the runner with token from GitHub (Repo Settings -> Actions -> Runners)
$ ./config.sh --url https://github.com/your-org/your-repo --token AEXXXXXXXXXXXXXXX

# 4. Install and start as a background systemd service
$ sudo ./svc.sh install actions-runner
$ sudo ./svc.sh start
$ sudo ./svc.sh status

3. Automated Ephemeral Workspace Pruning

Self-hosted runners store checked-out Git repositories and Docker build layers persistently in /home/actions-runner/actions-runner/_work. Over weeks of heavy building, dangling images and build caches will fill 100% of the disk.

Create an automated nightly cron maintenance script:

bash • /etc/cron.daily/docker-runner-prune 
#!/bin/bash
# Prune dangling Docker images and containers older than 48h
docker container prune -f --filter "until=48h"
docker image prune -af --filter "until=72h"
docker builder prune -af --filter "until=72h"

# Log disk status
df -h / | mail -s "Runner Disk Status" info@itxops.com
Pro Tip: Local Docker Cache Velocity
Because Docker layers remain on the local runner NVMe SSD, subsequent docker build steps take 3 seconds instead of 3 minutes downloading base layers from remote registries!

4. Using Your Runner in Workflow YAML

To target your self-hosted runner, simply update runs-on: in your workflow file:

yaml • workflow.yml 
jobs:
  test-and-build:
    runs-on: [self-hosted, linux, x64]
    steps:
      - uses: actions/checkout@v4
      - name: Run Test Suite
        run: |
          npm ci
          npm test
